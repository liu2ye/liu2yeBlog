# 事务

## 什么是事务？

+   事务是数据库操作最基本单元，逻辑上的一组操作，要么都成功，要么都失败，如果一个失败了，所有数据都会失败。

**只有DML数据操纵语言（insert delete update）才和事务相关**

**事务的存在是为了保证数据的完整性、安全性**

**假设所有的业务都能使用一条DML语句完成，就不需要事务机制了**

## 事务的四个特性

1.   原子性：不可分割，要么都成功，要么都失败
2.   一致性：确保事务将数据库从一个一致状态转换到另一个一致状态。事务执行前后，数据库必须遵守所有定义的完整性约束（如外键约束、唯一性约束等）
3.   隔离性：多个事务之间不会产生影响
4.   持久性：一旦提交对数据库的影响是永久的，即使数据库出现故障也不会丢失

## 事务之间的隔离性

事务隔离性存在隔离级别，理论上有四个级别：

1.   读未提交（read uncommitted）

     一个事务还未提交，另一个事务就可以读到了

     存在现象：脏读（Dirty Read）。读到了未保存到硬盘上的数据，如果此时断电了，就等于读到了假数据

2.   读已提交（read committed）

     一个事务提交之后的数据，另一个事务才能读取到

     存在问题：不可重复读。一个事务使用多次某一数据，数据不一致

3.   可重复读（repeatable read）

     解决了不可重复读

     存在问题：读到的数据是幻

4.   序列化读/串行化读

     解决了所有问题

     出现问题：需要事务排队，效率低

Mysql数据库的默认隔离级别是：读已提交

Oracle数据库的默认隔离级别是：可重复读



## 事务的传播行为

在一个事务开启后，如果在事务内涉及到了另一个事务的调用，是沿用主事务，开启新事物还是不接受事务。

+   REQUIRED：如果在事务内，沿用。否则自己开启一个事务。即保证自己在一个事务中
+   SUPPORTS：如果在事务内，沿用。否则不使用事务
+   MANDATORY：必须处在一个事务内，否则报异常
+   REQUIRES_NEW：在事务内：原事务暂停，开启自己的新事物；不再事务内直接开启事务
+   NOT_SUPPORTED：不支持事务，如果在事务中，暂停当前事务，按非事务执行
+   NEVER：不支持事务，如果在事务中，报异常
+   NESTED：与REQUIRES_NEW相似，不同的是：REQUIRES_NEW中新产生的事务完成后就会提交，NESTED会在完成后创建保存点，只有外层事务完成时才会一起提交，避免了脏读现象



## 演示事务

1.   使用**start transaction**来开启事务
2.   执行DML
3.   回滚**rollback**或者提交**commit**

```mysql
# 开启事务
START TRANSACTION; 

# 执行DML语句
INSERT INTO USER(id, NAME, sex, age) VALUES(8, 'ba', '男', 88);
# ......

# 回滚，事务结束
ROLLBACK;

commit; # 事务提交
```



## 总结

事务是为了解决完整的执行一个业务。在高并发的情况下，多个事务可能会操纵同一个数据，为了防止多个事务之间出现冲突，定义了隔离性。

隔离性是为了多个事务之间出现的冲突，隔离性的最高级别序列化不允许并发来完美解决。
